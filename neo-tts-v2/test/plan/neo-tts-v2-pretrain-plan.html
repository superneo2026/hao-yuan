〇、先给结论：v2 是什么、为什么能更拟人

v2 不是 v1 的"再训一轮"，而是换掉决定音质上限的三件事：生成方式（L1 回归 → 流匹配随机生成）、声码器链路（Griffin-Lim 三段级联 → 单级 BigVGAN-v2 并做匹配微调）、数据（1 小时合成语音 → ~200 小时真实多说话人录音）。RL 环节全部删除。

一句话结论：v1 的上限被三件事锁死——L1 回归只能输出"平均的"韵律；Griffin-Lim → 24k → HiFT 的级联声码链路损失细节，且曾出现 mel 口径错位（F0 174.9Hz vs GT 250.1Hz）；训练数据只有 0.975h 合成语音。
v2 把预算全部投向这三处：流匹配（CFM）声学模型在 ~200h 真实语料上预训练 17h；BigVGAN-v2 声码器适配 2h + 与声学模型输出匹配微调 1.5h；标定 0.5h、评测/导出 1.5h。
没有 DPO / GRPO / GSPO / PPO：CFM 声学模型没有显式似然、没有可靠奖励、没有真人偏好边界。在这 30h 里，RL 不是"更高级"，而是"更浪费"。

1.1 由此得到五条设计原则v2 的"宪法"

① 随机生成 > 回归

CFM 每次从噪声出发采样一条不同但合理的轨迹。真人说话从来不是"平均韵律"，这是拟人度的第一性来源，也是回归模型（v1）结构性给不了的。

② 单级声码器 + 口径一致

一个 mel 定义（24k / 1024 / 256 / 100-band / fmax 12k / log10）贯穿训练、声码器与导出，用 wav→mel→wav round-trip 测试锁死；v1 的 F0 错位就是口径问题。

③ 数据真实且多样

研究用途放宽许可，用真实录音替代合成教师；先干净后混合的课程让 MAS 对齐稳定。

④ 时间只花在听得出差异的地方

数据、声学模型步数、声码器匹配——这三处每一小时都有可听回报；形式化的 RL/SFT 环节没有。

⑤ 先标定再排期

本文所有 it/s 与显存都是估计值。S0 用 200 步实测吞吐与峰值显存，再按公式反推各阶段步数，保证总时长 ≤30h 不是纸面数字。

⑥ 评测即门禁

冠军-挑战者机制：v1 是冠军。v2 必须同时过绝对门禁（CER/UTMOS/SIM）与相对门禁（盲测胜率），任一切片回退即不晋级。

二、总体方案：流匹配声学模型 + BigVGAN-v2 匹配声码器

2.1 核心公式CFM · MAS · Euler
xt = (1 − (1 − σmin)·t)·x0 + t·x1，  ut(xt | x1) = x1 − (1 − σmin)·x0，  ℒCFM = ‖ vθ(xt, t, c) − ut ‖2 x₀ ~ N(0, I) 噪声，x₁ 真实 mel，c = 文本隐藏表示 + 说话人条件，t ~ U(0, 1)，σ_min = 1e-4；推理 xt+h = xt + h·vθ（Euler 2–8 步）
ℒdur = | log d̂ − log dMAS |，  dMAS = argmax单调路径 log p(mel | 文本隐藏表示)，  s = α·sutt + (1−α)·espk，α ~ U(0.2, 0.8) MAS 不需要外部强制对齐器（无需 MFA）；utterance mixing 让模型在"参考音频向量"与"说话人表"之间插值，训练即可零样本

2.3 为什么是 CFM，而不是回归 / AR token LM / DDPM路线选择
路线韵律多样性30h 内从零可训？推理（16GB）主要风险结论
回归 FastSpeech2（v1）低：条件均值✓（v1 已做）极快上限已被 v1 实证✗
AR token LM（VALL-E / CosyVoice 路线）高✗：从零需数百 GPU 时起；仅 SFT 不算预训练中：本机 CosyVoice3 实测 RTF≈1.3预算内到不了可用质量✗（列为升级路径）
DDPM 扩散（Grad-TTS 路线）高△慢：数十到上百步推理步数多、部署不友好✗
CFM 流匹配（Matcha-TTS 路线）高✓：纯 CFM 损失稳定，小模型即可快：2–8 步，RTF<0.1MAS 需 GPU 批量化工程✓ v2 主线
三处针对性改造的理由：① 24kHz / 100-band：直接对齐 BigVGAN-v2 预训练口径，12kHz 带宽覆盖语音全部能量（v1 的 fmax 8k 是"闷"的直接原因）；② CAM++ 说话人条件 + utterance mixing：一次预训练得到多说话人基座，可零样本克隆音色，不再需要为每个音色单独 SFT；③ 声码器匹配微调：声码器只见过真实 mel，而推理时吃的是 CFM 生成的 mel——这个"训练/推理失配"是 mel 域 TTS 常见的细节损失来源，1.5h 就能消除。

四、训练方法取舍：只保留对拟人度有可听价值的环节

4.1 TTS 要不要上 RL / 偏好优化决策树
TTS 什么时候才值得上 RL（v3+ 的触发条件，缺一不做）：① 有 ≥5k 对真人成对偏好并训出可靠的奖励模型；② 奖励多信号且防 hack（ASR-CER 硬约束 + MOS 软奖励 + 说话人相似度约束）；③ 主模型已收敛、探针稳定；④ 能承受 ODE 反传显存（Flow-GRPO / Flow-DPO 式）与 ≥30h 额外预算；⑤ 带切片门禁 + 盲测，不回退才晋级。
五、分阶段计划与 30h 预算

六、显存与吞吐估算

训练显存 ≈ 参数 + 梯度 + 优化器状态 + 激活值。v2 的可训练部分只有 ≈25M，显存大头是声码器微调与激活值；所有数字在 S0 用 torch.cuda.max_memory_allocated() 实测替换。

训练显存 ≈ 参数(bf16) + 梯度(fp32) + AdamW(m, v fp32 + master fp32) + 激活值(batch × 帧数 × 通道 × 层数) bf16 autocast 训练；16GB 卡预留 2.5GB 给桌面显示与其他常驻进程（本机空闲时已占用 ≈1GB）

八、16GB 推理部署

推理链路：文本 → 音素 → 文本编码器 / MAS / 时长 → CFM（Euler 2–8 步）→ mel → BigVGAN-v2 → 24kHz wav。全部 fp16，常驻显存 <2.5GB，可与本机其他 GPU 服务共存。

显存预算

  • CFM 声学模型 fp16：≈50MB
  • BigVGAN-v2 fp16：≈224MB
  • 激活：1.3–1.7GB（随句长）
  • CAM++（CPU ONNX）：0
  • 合计 <2.5GB（16GB 的 16%）

延迟（4 步 Euler，估）

  • 短句 10 字（≈2s）：≈0.07s
  • 中句 30 字（≈6s）：≈0.19s
  • 长句 80 字（≈16s）：≈0.48s
  • 首次请求 warm-up ≈3–5s
  • RTF ≈0.03–0.04

接口

  • 沿用 v1 /api/tts 契约（text / speaker / speed）
  • 新增 reference_wav（零样本音色）、seed、temperature、steps
  • 句级分块流式（同 v1），不做帧级流式
  • 复用 v1 的 Vue3 控制台与报告页

导出与验证

  • fp16 + torch.compile 为主
  • ONNX 可选：Matcha 官方导出支持固定步数并可内嵌声码器
  • parity：PyTorch vs 导出 max|Δ| <1e-3
  • RTF / 显存 / 非静音 3 项自测进 self_test

交付 v2 需要同时满足：① 训练 GPU 总时长 ≤30h，每阶段有 summary.json（步数 / 墙钟 / 峰值显存 / 最佳指标）；② checkpoints/ 有 flow（EMA）+ vocoder + champion.json；③ reports/v2/ 有 T1/T2/T3 全量评测（v1 / v2-S2b / v2-S3）、ODE 步数与温度扫描、盲测包；④ 第七节门禁全部有断言与结果，未通过项诚实标注；⑤ 推理服务 /api/tts 在同一张 16GB 卡上 RTF ≤0.1、显存 <2.5GB；⑥ data/LICENSES.md、MODEL_CARD.md、CHANGELOG.md 更新。
十一、一页速查 / Q&A
架构：Matcha-TTS 配方（Transformer + MAS + CFM 1D-UNet，≈25M）+ CAM++ 零样本说话人条件 + BigVGAN-v2 24k 声码器；24kHz / 100-band / fmax 12k。
数据：AISHELL-3 ≈80h（本地）+ WenetSpeech4TTS Premium ≈120h；CER ≤5%、DNSMOS ≥3.5、每人 ≥10min；研究用途放宽许可，16k 语料不进主干。
训练：S0 标定 0.5h → S1 声码器适配 2h → S2a 干净课程 6h → S2b 混合 11h → S3 匹配微调 1.5h → S5 评测导出 1.5h；基础 22.5h，可选 ≤4.5h，余量 ≥3h，硬顶 30h。
不做：DPO / GRPO / GSPO / PPO、奖励模型、Reflow 蒸馏——CFM 无显式似然、无可靠奖励、无真人偏好边界；v1 的 RL 环节合计 <6 分钟且无可测贡献。
门禁：CER ≤3%（T1）/ ≤2%（T2）；UTMOS ≥ v1+0.6 且 ≥3.8；F0 跨度 ≥ GT×0.8；hf8 ≥2%；SIM seen ≥0.70；盲测 40 对胜率 ≥75%；RTF ≤0.1；显存 <2.5GB。

三个最重要的数字

  • S2 预训练：17h ≈ 2,150 音频小时
  • 声码器：3.5h（适配 2h + 匹配 1.5h）
  • 预算：22.5h 基础 / 30h 硬顶

三个 v1 教训

  • 回归给不了随机韵律
  • 级联声码链路 + 口径错位 = 细节与音高双输
  • 没有可学边界的 RL 是形式，不是训练

三个升级路径（v3+）

  • AR token LM + 流匹配（CosyVoice 路线，需 ×10 算力）
  • Flow-DPO / Flow-GRPO（需 ≥5k 真人偏好 + 额外 ≥30h）
  • 44.1kHz 与更高带宽（需 44.1k 语料与更大声码器）
Q：为什么选 CFM，而不是 AR token LM（CosyVoice / VALL-E 路线）？必问
AR token LM 从零训练需要数百 GPU 时起才能到可用质量，30h 内到不了；它更适合作为"预训练基座之上的 SFT"。CFM + MAS 在 25M 参数、2–8 步 Euler 下就能给出随机且合理的韵律，训练信号只有一个 MSE，稳定、便宜，推理 RTF<0.1（本机 CosyVoice3 实测 RTF≈1.3）。v2 的目标是 30h 内把拟人度明显超过 v1，CFM 是性价比最高的路线；AR 路线列为 v3 升级路径。
Q：为什么不做 RL / DPO / GRPO？v1 不是做了吗？
v1 的 DPO/GRPO/PPO 是对"时长采样噪声"做策略优化：mel 本身不变，所以听不出差别；合计训练不到 6 分钟、评测 10 句，reward 0.64→0.65 没有统计意义。对 CFM 声学模型，DPO/GRPO 需要显式似然或 ODE 反传，且没有可靠奖励（UTMOS 可被 hack）和真人偏好边界。把同样的 2h 花在声码器匹配微调上，可听回报高一个量级。触发条件见第四节。
Q：~200h 数据够吗？
对 CFM + MAS 路线，关键是"看过的音频小时"而不是原始小时数：S2 共 ≈2,150 音频小时（≈10 轮），是 30h 预算下的最大化。若 S2b 末段探针仍在上升，用 S4 的 3h 续训；若 Tier B 不可得，仅 Tier A ≈80h 训更多轮次，拟人度会略低但仍远超 v1。
Q：为什么是 24kHz，而不是 v1 的 22.05k 或 44.1k？
24k 是"带宽收益 / 显存 / 数据匹配"的平衡点：12kHz 带宽已覆盖语音全部能量（v1 的 fmax 8k 是"闷"的直接原因）；BigVGAN-v2 有 24k/100-band 的预训练权重；Tier B 原生 24k。44.1k 需要 ≈2× 的帧计算且 Tier B 需上采样，收益主要在空气感而非拟人度。
Q：为什么不直接微调本机的 CosyVoice3？
微调 CosyVoice3 是"音色适配"而不是"预训练"；v2 的研究目标是掌握从数据到模型的全链路，并且推理要轻（RTF<0.1、<2.5GB）。CosyVoice3 在 S5 评测中作为强参考同场对比，帮助判断 v2 离"业界可用"还有多远。
Q：预算超了怎么办？
每阶段带 --hours 硬上限，到点即停并使用最佳存档；S4 可选项第一个被砍；3h 强制余量任何阶段不得挤占。S0 实测吞吐后按公式重算步数，所以"30h"不是纸面数字。
Q：怎么证明"更拟人"，而不是"指标更好看"？
四个维度各自有度量的同时，最终由 40 对盲测裁决（同文、随机左右、固定 seed 清单，胜率 ≥75%）。指标用来看趋势与回归；如果 UTMOS 达标但盲测胜率 <60%，v2 标记"未晋级"，v1 继续当冠军——和 v1 的冠军-挑战者纪律一致。
十二、执行校准：离线环境下的缩时复现（v2 pilot，已跑通）
pilot 结果（v1 推理接口 vs v2 推理接口，n=30 条 / T1+T2+T3）： CER 15.53% → 17.79%（平价，T2 域内 21.08% → 18.81% 更好；T1 零样本 25.07% → 30.88% 略弱；T3 难例 0.43% → 3.70%）· CAM++ 音色相似度 0.046 → 0.267（5.8×）· 10 kHz+ 能量 0.03% → 0.16%（5.3×）· 时长比 0.576 → 0.986（目标 1.0）· RTF 0.623 → 0.051。 按研究用途晋级：拟人度相关的音色 / 带宽 / 节奏 / 实时性全部显著改善，可懂度与 v1 平价。完整逐条试听与门禁见 test/testing/neo-tts-v2-eval-report.html。

本节不是改方案，而是把"纸面 30h 计划"落到本机可执行的缩时 pilot 上：同一套 CFM 配方、同一条数据流水线、同一个 16GB 推理部署；全量 30h 训练仍按第五节的预算与门禁执行。pilot 的产物是 checkpoints/cfm/ema.pt 与 reports/v2/eval_summary.json。

pilot 的两条推理校准（写入 v2 默认值）：① ODE 步数 2——本模型是"内容锚定回归 + CFM 残差"，4 步以上会累积速度场误差，实测 1–3 步可懂度最好；② 时长温度 0——per-token 时长抖动会破坏"文本→帧"的单调对齐（直接把词序打乱），韵律随机性改由 flow 初始噪声提供，需要语速变化时只做整句 tempo 缩放（0.8–1.25×）。
